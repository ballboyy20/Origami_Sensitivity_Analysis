==============================================================================
ADDENDUM -- root-cause finding: the log_det tie-break mostly does NOT fix the
degenerate decode, and the original "(u_i,v_i) near (0,0)" diagnosis was WRONG
==============================================================================
Only 2/33 severely-broken DE-converged subsets crossed back above 10% of DE's
own lambda_min, and none of the 5 DE-failed "full-rank reference existed"
subsets improved at all. Before accepting that as simply "stage 2 mostly
doesn't help," a follow-up ad hoc investigation (not part of the automated
sweep -- run by hand against a handful of the 33 severely-broken subsets)
checked WHY, by inspecting the raw (u_i, v_i) magnitudes stage 1 and stage 2
each actually return (not just the decoded theta / achieved lambda_min):

  - The original hypothesis (this repo's prior sdp_size9_summary.txt) was that
    non-binding couplings' (u_i, v_i) sit near the degenerate (0, 0) point,
    which decode_uv_to_theta() then turns into an arbitrary angle. This is
    FALSE for essentially every case checked: e.g. champion subset (indices
    0,1,2,3,5,6,7,8,11) has all 9 magnitudes in [0.98, 1.0]; subset
    [0,1,2,3,5,6,7,10,11] (one of the 5 "full-rank-ref" DE-failed cases) has
    magnitudes as low as 0.767 but nothing near 0 -- yet its achieved
    lambda_min is 5.5e-7, essentially zero. Magnitude-near-zero is NOT the
    actual failure mode in these cases.
  - Replacing log_det with an entirely different concave tie-break
    (cp.tr_inv -- a pure LMI/Schur-complement formulation, no exponential
    cone, so a different numerical path through the solver) gives the
    SAME decoded theta and the SAME achieved lambda_min on the champion
    subset (0.008712 either way). Two unrelated concave objectives landing
    on the same answer rules out "log_det's specific exp-cone
    canonicalization is numerically unreliable" as the explanation.
  - Comparing stage 1's own (u, v) to stage 2's for the same subset shows
    they are nearly IDENTICAL (e.g. subset [0,1,2,3,5,6,7,10,11]: stage-1
    magnitudes [0.978, 0.956, 1, 0.852, 1, 1, 1, 1, 0.767], stage-2
    [0.977, 0.955, 1, 0.852, 1, 1, 1, 1, 0.767]). This is the actual
    mechanism: stage 2's feasible region is capped at t_floor = t* - tol,
    a band only ~1e-7*t* wide around stage 1's own optimum. For topologies
    where stage 1's t*-maximizer is essentially UNIQUE, that band contains
    only points extremely close to stage 1's own (u, v) -- there is no
    genuinely different, better-decoding point for log_det (or any other
    tie-break) to move to. The tie-break can only help when stage 1's
    optimum is achieved by a genuine FAMILY of tied points, which isn't
    the case for most of these subsets.
  - The deeper issue: for many of these subsets, stage 1's t* itself is
    achieved at a point with one or more (u_i, v_i) meaningfully INSIDE
    the unit disk (not just infinitesimally, e.g. magnitude 0.77-0.85).
    That interior point is a mathematical average/blend with no single
    real theta behind it -- K_reduced(u, v) there is not C(theta)^T C(theta)
    for any actual theta. t* is a valid bound on it regardless (SDP
    duality doesn't care), but ANY decode of a point near it -- via angle
    alone, regardless of which secondary objective chose it -- is decoding
    a blend, not a real configuration, so a large real-eigenvalue shortfall
    should be expected. This is a genuine RELAXATION GAP for these specific
    topologies (the convex relaxation is loose), not a decode-selection-
    among-ties problem, so no tie-break confined to a tight band around t*
    can fix it by construction.

Practical implication: sdp_lambda_min's t* remains a sound, valid upper
bound everywhere (soundness check above still passes). But treat the
decoded theta / achieved lambda_min as reliable mainly when the reported
gap is already small (as it is for the two-panel case, and forthe best
subsets in this sweep) -- a large gap is a signal the relaxation itself is
loose for that topology, not just that decode got unlucky, and a further
lexicographic tie-break at fixed t will generally not recover it. Closing
these large-gap cases would need either a fundamentally tighter relaxation
(e.g. additional valid cuts) or a genuine nonlinear local polish seeded from
the SDP's decode -- both out of scope for this task and not yet attempted.
